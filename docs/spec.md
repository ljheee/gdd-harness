# GDD 控制台 Mac app — 规格

## 规格

### 1. 产品形态

- 交付物是一个 macOS 桌面 app，使用 **Tauri 2**，macOS 上由系统 **WKWebView** 渲染；不使用 Electron，不内置 Chromium。
- app 是一个“壳 + 本机进程监管者”：它不实现控制台页面，不复制 `gdd/ui.py` 的内嵌 HTML，也不打包任何前端静态资源。窗口直接加载 `http://127.0.0.1:8765/`。
- app 不新增应用层监听端口（不监听 8765 或其他业务端口），不代理控制台流量，不修改控制台的绑定地址。
- app 不直接读写任务的 `.gdd/state.json` 等状态；任务状态仍由控制台和 GDD 引擎管理。

### 2. 启动与复用行为

app 启动（以及从 Dock 重新打开窗口）时按以下顺序执行：

1. **读取并校验配置**：至少需要 GDD 源码根目录、Python 解释器路径、工作台目录。配置无效时按第 8 节报错，不启动控制台。
2. **探测本机 8765**：对 `http://127.0.0.1:8765/api/overview` 发起只读 `GET` 请求（短超时，具体值由方案确定）。
   - 返回 `200`，响应是 JSON 对象，且包含 `ok: true`、`templates` 数组、`tasks` 数组：判定为已有 GDD 控制台，**直接复用**，不启动第二个进程，打开窗口加载 `http://127.0.0.1:8765/`。
   - 连接被拒绝（端口无监听）：进入第 3 步，启动控制台。
   - 端口有响应但不是上述 GDD 形状，或返回其他状态码/非法 JSON：按“8765 被非 GDD 服务占用”报错，不启动第二个控制台，也不把该服务加载进窗口。
3. **启动控制台**：使用配置的 Python 解释器执行等价于以下 argv 的命令（不得经过 shell 字符串拼接）：
   - `<python> -m gdd.ui --root <工作台目录> --port 8765 --no-open`
   - 子进程环境需满足：`PYTHONPATH` 包含配置的 GDD 源码根目录；`PATH` 包含配置的额外目录（用于找到 Agent CLI）；配置中显式提供的环境变量原样传入。
   - app 不依赖自身的工作目录；`--root` 必须是绝对路径。
   - 捕获控制台的 stdout/stderr 并重定向到本地日志文件（不要只接到 app 的管道），供启动失败诊断，并保证 app 退出后控制台仍可正常写日志。
4. **等待就绪**：在方案规定的就绪上限内（不超过 30 秒）轮询 `/api/overview`，判定标准与第 2 步相同。就绪后打开窗口。
5. **启动超时**：终止本次由 app 拉起的控制台子进程（仅限本次拉起的进程），按第 8 节报错并给出日志路径；不打开空白窗口。

补充规则：

- 复用已有控制台时，app 不知道也不改变其工作台目录；配置中的工作台只在 app 自行拉起控制台时生效。
- 探测只允许只读请求；app 不得在探测阶段向控制台发送 `POST`/`PUT`/`DELETE`。
- 控制台已在运行时，app 启动后不重复启动；若用户先手动在 8765 启动了控制台，app 复用同一实例。

### 3. 配置

- app 必须持久化以下配置，且用户无需重新构建/发布 app 即可修改：
  - GDD 源码根目录（包含 `gdd/` 包，能执行 `python -m gdd.ui`）；
  - Python 解释器路径（必须指向 Python ≥3.10）；
  - 工作台目录（默认 `~/gdd-workbench`）。
- 可选配置：
  - 额外 `PATH` 目录列表（用于 GUI 启动时找到 `claude`/`codex` 等 Agent CLI）；
  - 额外环境变量（如 `GDD_AGENT_BIN`、`GDD_AGENT_PRE_ARGS`），启动控制台时合并到子进程环境。
- 配置的存储位置、文件格式和首次启动引导方式由方案设计确定，但必须满足：
  - 重启 app 后配置仍然有效；
  - 配置缺失或无效时，app 给出可操作的错误/配置引导（指出字段/路径），不静默使用当前目录或错误的解释器；
  - 配置中若包含密钥类环境变量，不得写入日志；配置若落盘，文件权限应为仅当前用户可读写。
- 配置在 app 启动时读取；修改配置后需重启 app 生效（本迭代不要求热加载）。

### 4. 工作台目录

- 默认工作台为 `~/gdd-workbench`。目录不存在时，控制台启动过程会创建它（`gdd/ui.py:1258-1259`）；app 也可以预先确保其存在。
- app 必须以绝对路径把工作台传给 `--root`；不得依赖 app 启动时的当前目录。
- 工作台路径存在但为普通文件、不可创建或不可写时，按配置/启动错误处理，不启动控制台。
- 复用已有控制台时，以已有控制台实际使用的工作台为准，app 不重启、不迁移其任务。
- 本迭代不提供 GUI 工作台选择器；通过配置入口修改。

### 5. 端口与控制台识别

- 本迭代固定使用默认端口 **8765**，只监听/连接 `127.0.0.1`。
- 不支持自动发现非默认端口上的已有控制台；若用户在 9000 等端口自行启动控制台，app 不会复用它，而是按 8765 的流程启动/复用。
- 识别契约：`GET http://127.0.0.1:8765/api/overview` 返回 `200` 且 JSON 包含 `ok: true`、`templates` 数组、`tasks` 数组。该接口是既有控制台 API（`gdd/ui.py:1086-1089`），app 只读调用，不修改它。
- 8765 被非 GDD 服务占用时，app 报错并停止；**不退让到其他端口**，避免窗口地址与复用契约漂移。

### 6. 窗口行为

- app 使用单个主窗口，直接加载 `http://127.0.0.1:8765/`。不得使用本地 HTML 包装页、iframe 代理或第二份前端。若 Tauri 构建流程必须提供一个本地占位入口，该入口只能做初始化/跳转，不得复制或渲染控制台 UI；窗口最终必须显示控制台页面。
- 窗口只允许加载 `127.0.0.1:8765` 的控制台页面；不应导航到外部 origin，也不应向该远程页面暴露 Tauri 的文件系统/IPC 能力（页面只通过 HTTP 与本机控制台交互）。
- 关闭主窗口不退出 app；点击 Dock 图标可重新打开窗口。重新打开时重新执行第 2 节的探测/复用流程。
- 控制台在窗口使用期间异常退出时：若窗口尚未加载完成，显示 WebView 的加载/连接失败；若页面已加载，保留最后渲染的页面，后续轮询/SSE 请求失败。本迭代不自动重启控制台；用户可退出并重新启动 app 触发重新探测/拉起。

### 7. 生命周期

- app 自行启动的控制台在以下情况都继续运行：
  - 关闭主窗口；
  - 退出 app（`Cmd+Q`）；
  - app 崩溃（子进程不作为 app 的陪葬进程被杀）。
- app 退出时不得向控制台子进程发送终止信号；控制台的 stdout/stderr 已重定向到文件，不依赖 app 的管道存活。
- 下次启动 app 时通过 8765 探测并复用该控制台，不重复启动。
- app 不终止不是自己启动的控制台；对用户先在终端启动的实例，app 退出后其进程保持存活。
- 唯一的自动终止场景：app 启动了控制台但在就绪上限内未就绪，app 终止**本次拉起的子进程**并报错。
- 本迭代不提供“停止控制台”的 GUI 入口；需要停止时由用户在终端/活动监视器中结束进程，文档给出说明。

### 8. 错误与失败语义

| 场景 | 用户可见行为 | 是否启动控制台 |
|---|---|---|
| 配置缺失/无法解析/必填字段为空 | 显示错误或配置引导，指出配置入口与字段；不打开窗口 | 否 |
| GDD 源码路径不存在或不含 `gdd` 包 | 显示错误，指出路径与期望的包结构；不打开窗口 | 否 |
| Python 路径不存在/不可执行/版本 <3.10 | 显示错误，指出解释器路径与最低版本 3.10；不打开窗口 | 否 |
| 工作台路径是普通文件或不可写 | 显示错误，指出工作台路径；不打开窗口 | 否 |
| 8765 被非 GDD 服务占用 | 显示“端口被非 GDD 服务占用”类错误；不打开窗口 | 否 |
| 控制台启动后在就绪上限内未就绪 | 显示错误与本次控制台日志路径；不打开空白窗口 | 启动过，随后终止本次子进程 |
| 控制台运行期间异常退出 | 窗口保留最后页面，后续轮询/SSE 失败；不自动重启 | 否（用户重启 app 可重试） |

- 所有错误信息应可操作：至少包含涉及的字段/路径/端口，以及下一步建议。
- app 不得因上述错误崩溃或进入无限重启循环。
- 日志不得记录配置中的密钥类环境变量值。

### 9. 安全

- 控制台只监听 `127.0.0.1`（`gdd/ui.py:1262`）；app 不改变这一点，不新增监听端口，不做反向代理。
- app 直接加载控制台页面，保持同源；页面自带的 `X-GDD-Request` 头（`gdd/ui.py:677`）与既有 Host/CSRF 校验（`gdd/ui.py:1043-1070`）继续生效，app 不需要也不应放开 CORS。
- app 启动子进程使用 argv 数组，不经过 shell 拼接，避免工作台路径等配置被解释为 shell 语法。
- app 不将 Tauri 的文件系统/进程 IPC 能力暴露给远程页面；页面能力限于同源 HTTP 调用本机控制台。
- app 创建的配置/日志数据不应对其他用户可读；配置中的密钥类环境变量不落日志。

### 10. 更新与兼容

- app 只依赖控制台的既有契约：`python3 -m gdd.ui`、`--root/--port/--no-open`、`GET /`、`GET /api/overview`、仅监听 `127.0.0.1`。
- 本迭代不要求修改 `gdd/ui.py`；控制台既有 CLI 与 HTTP 行为保持兼容。
- GDD 源码/包位于 app 之外。页面 HTML 在控制台进程启动时载入；更新 GDD 源码后，必须重启使用该源码的控制台进程才能加载新页面。由于 app 默认复用已运行的控制台，仅重启 app 不会加载新代码；需要先停止旧控制台（确保 8765 无监听），再启动 app 让其拉起新代码。**不需要重新构建/发布 app**。app 不打包、不复制 `gdd/ui.py` 或 HTML。
- 若未来控制台修改 `/api/overview` 的返回结构，app 的识别逻辑需要同步升级；在结构不匹配时 app 应报“无法识别已有服务”，而不是误判为控制台或盲目启动第二个实例。
- app 版本与控制台版本独立；app 不检查、不强制控制台版本。

### 12. 非目标（本迭代）

- 非默认端口发现、动态端口分配。
- 在未安装 Python/GDD 的机器上独立运行、捆绑 Python/GDD。
- GUI 工作台目录选择器、GUI 设置面板、停止/重启控制台按钮。
- 控制台异常退出后的自动重启、多 app 实例协调。
- Windows/Linux 版本、Mac App Store、签名与公证、app 自动更新。
- 修改 GDD 控制台的页面、API 或任务状态机。
