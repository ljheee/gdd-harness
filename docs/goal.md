# GDD 控制台 Mac app — 目标与验收标准

> 依据：`docs/requirement.md`（需求描述第 7–11 行、待澄清问题第 15–18 行）与 `docs/survey.md`。
> 本节点对 requirement 中 4 个待澄清问题给出提议结论；结论需在本节点审批中确认，审批通过后作为后续验证的基线。

## 目标

### 产品目标

为现有 GDD Web 控制台提供一个 macOS 桌面入口：

1. 使用 **Tauri 2** 构建 Mac app，macOS 上使用系统 **WKWebView**，不使用 Electron 或内置 Chromium。
2. app 窗口**直接加载** `python3 -m gdd.ui` 提供的页面（`http://127.0.0.1:8765/`），不重写界面，不在 app 内打包第二份前端或静态资源副本。
3. app 启动时：
   - 若本机 `127.0.0.1:8765` 已有可识别的 GDD 控制台在运行，直接打开该地址，不重复启动控制台；
   - 若没有，则使用本机已有的 Python（≥3.10）与 GDD 源码拉起控制台，待其可访问后打开窗口。
4. 控制台只监听 `127.0.0.1`；app 自身不监听端口、不对外暴露控制台。
5. Web 界面更新通过更新外部 GDD 源码生效；**更新 Web 页面不需要重新构建或发布 app**。
6. app 需要记住并在启动时使用一个“工作台目录”（其下每个子目录是一个任务），默认 `~/gdd-workbench`；目录不存在时由控制台创建。

### 澄清结论（本节点提议，审批通过后生效）

| 待澄清问题 | 本节点结论 | 依据与理由 |
|---|---|---|
| Q1：app 启动控制台使用哪个工作台目录？是否需要用户选择或记住？ | 需要一个持久化的工作台目录；默认 `~/gdd-workbench`，不存在时允许控制台创建；用户可通过 app 的配置入口修改；本迭代不做首次启动的目录选择器 | 文档已把 `~/gdd-workbench` 作为推荐工作台（`README.md:41-42`、`USER_GUIDE.md:289-291`）；`--root` 默认当前目录（`gdd/ui.py:1253`）在 GUI 启动时不可控 |
| Q2：已有控制台使用非默认端口时如何确定地址？是否只涵盖 8765？ | 本迭代**只处理默认端口 8765**；不自动发现非默认端口。8765 被非 GDD 服务占用时报错，不退让到其他端口 | 控制台不公布端口、无实例发现机制（`gdd/ui.py:1250-1266`）；需求核心场景是“已在跑时直接打开”，默认端口足以覆盖 |
| Q3：app 是否在未预装 Python/GDD 的机器上独立运行？Python/GDD 及其 Web 更新从哪里获取？ | **不承诺独立运行**。app 依赖本机已有的 Python ≥3.10 与 GDD 源码；两者均不打包进 app，由用户配置/提供；Web 更新通过更新该 GDD 源码生效 | `requires-python >=3.10`（`pyproject.toml:9`）；控制台需 `PYTHONPATH` 或安装包（`docs/survey.md` 实测）；不打包才能满足“Web 更新不重发 app” |
| Q4：app 自行启动的控制台在窗口关闭后继续运行还是随 app 退出？ | **继续运行**。关闭窗口或退出 app 不终止控制台；下次启动 app 通过 8765 探测并复用；app 不终止非自己启动的控制台；启动超时失败时只终止本次拉起的子进程 | GDD 任务可能长时间运行（`gdd/runner.py:5-10` 的会话超时默认 7200 秒）；控制台无生命周期/停止接口（`gdd/ui.py:1267-1269`） |

### 本迭代不纳入的功能（待澄清）

以下功能与目标相关，但**未写入上表结论，也不进入本次验收标准**；若需要，应在后续澄清中明确：

- 非默认端口上已有控制台的自动发现。
- 在未安装 Python/GDD 的机器上独立运行，或由 app 捆绑 Python/GDD。
- GUI 工作台目录选择器、GUI 设置面板。
- 从 app 内停止/重启控制台的按钮或菜单。
- Windows/Linux 版本、Mac App Store 分发、Developer ID 签名与公证。
- app 自动更新、多 app 实例协调、控制台异常退出后的自动重启。

## 验收标准（DoD）

> 优先级：P0 核心必须达成；P1 重要；P2 边界与文档。验证层级：e2e / integration / unit / static。
> 所有测试数据在运行时生成（临时目录、随机后缀、fake 可执行文件），不依赖固定用户目录或固定测试数据；不得把某条具体测试数据写死为验收前提。

| ID | 优先级 | 验证层级 | 验收判据 | 数据与复现方式 |
|---|---|---|---|---|
| D1 | P0 | static | 工程使用 Tauri 2，macOS 目标使用系统 WKWebView；依赖与构建产物中无 Electron/Chromium；app 包内不含 GDD 控制台页面/前端副本，窗口最终加载 `http://127.0.0.1:8765/`；若 Tauri 构建必须带本地占位入口，占位内容只能是初始化/跳转，不得复制或渲染控制台 UI | 检查 `src-tauri` 的 Tauri 配置与依赖清单；对构建出的 `.app` 做资源清单和关键字扫描；无需测试数据 |
| D2 | P0 | integration | 8765 无监听时，app 用已配置的 Python（≥3.10）执行 `-m gdd.ui --root <工作台> --port 8765 --no-open`；进程命令行包含该工作台与 `--no-open`；在方案规定的就绪上限（不超过 30 秒）内 `GET /api/overview` 返回 200 且 JSON 含 `ok:true`、`templates`、`tasks`；窗口目标 URL 为 `http://127.0.0.1:8765/` | 临时 GDD 源码副本 + 临时空工作台；测试前确认 8765 未被监听；运行时记录子进程 argv 与 HTTP 响应 |
| D3 | P0 | integration | 先启动一个真实控制台（唯一临时工作台与任务），再启动 app；app 不产生第二个 `gdd.ui` 进程；原控制台 PID 不变；窗口 URL 指向同一 8765；页面任务列表来自原工作台 | 运行时生成随机任务名（如 `task-<随机后缀>`）；记录原 PID、进程数与任务列表 |
| D4 | P0 | e2e | 构建并启动 `.app` 后出现至少一个窗口，窗口内容为控制台页面（可见 `GDD 控制台` 标题/关键 UI 与预置任务名）；窗口目标地址为 `http://127.0.0.1:8765/` | 临时工作台内生成随机任务名；窗口截图 + 窗口标题/可访问性文本作为证据；若自动化取不到文本，降级为截图人工核对并保留截图 |
| D5 | P0 | integration | 用 GDD 源码副本 A 启动 app，确认页面可访问；停止该控制台进程（确保 8765 无监听，模拟 Web 更新后的重启）；在 A 的页面写入运行时生成的随机标记；重新启动 app（**不重新构建 app**），在方案规定的就绪上限内确认页面出现该标记；app 二进制哈希前后一致 | 运行时生成 UUID 标记写入临时副本；`shasum` 记录 app 二进制哈希；停止/重启控制台是测试步骤，不是 app 行为 |
| D6 | P0 | integration | app 运行后，8765 只监听 `127.0.0.1`（不是 `0.0.0.0`/`::`）；用本机非回环地址连接 8765 失败；app 主进程不监听 TCP 端口 | `lsof -nP -iTCP:8765 -sTCP:LISTEN`；本机非回环 IP 从 `ifconfig` 获取；若 WebKit 系统辅助进程出现内部监听，需在报告中单独说明，但不得新增对外应用端口 |
| D7 | P1 | integration | 工作台 R1 下预置生成的任务 T1，R2 下预置 T2；配置指向 R1 启动后，页面与 `/api/overview` 只列出 T1；停止该控制台并确保 8765 无监听；切换配置到 R2 并重启 app 后只列出 T2 | 临时 R1/R2 + 随机任务名；不读写用户现有工作台；停止/重启控制台是测试步骤 |
| D8 | P1 | unit | 配置校验逻辑对以下情况返回可定位的错误：必填字段缺失、GDD 源码路径不存在、Python 路径不存在、工作台路径为普通文件；错误包含字段名与路径，不抛未捕获异常 | 单元测试构造配置对象与临时路径；用普通文件模拟非法工作台 |
| D9 | P1 | integration | 使用无效配置启动 app 时，app 不启动控制台（`gdd.ui` 子进程数为 0），显示指向具体配置项/路径的可操作错误，app 不崩溃 | 临时配置指向不存在路径；统计子进程数；截图/日志作为提示证据 |
| D10 | P1 | unit | Python 版本校验：解释器报告版本低于 3.10 时拒绝启动，并提示最低版本 3.10；报告 ≥3.10 时通过 | 生成 fake Python 可执行文件输出不同版本号；不依赖本机真实解释器版本 |
| D11 | P1 | integration | 8765 被非 GDD 服务占用时（返回非 GDD 形状的 HTTP 响应），app 不启动第二个控制台，不把该服务当作控制台加载到窗口，显示端口冲突/未知服务错误 | 临时启动 dummy HTTP 服务监听 8765，构造非 GDD 响应 |
| D12 | P1 | integration | app 自行启动控制台后，关闭窗口并退出 app，控制台进程仍存活且 `/api/overview` 可访问；再次启动 app 复用该控制台、不产生第二个进程 | 临时工作台；记录 PID 与进程数；仅覆盖“app 启动”场景 |
| D13 | P1 | integration | 用户先在外部启动控制台，再启动 app；app 退出后该外部控制台进程仍存活（PID 不变）且 `/api/overview` 可访问 | 临时工作台；记录外部控制台 PID；仅覆盖“外部启动”场景 |
| D14 | P2 | static | 构建出的 `.app` 不包含 Python 运行时/framework，也不包含 `gdd` 源码或页面副本；README/使用文档明确要求本机已安装 Python ≥3.10 与 GDD 源码 | 对 `.app` 做文件清单与关键字检查；检查文档文本 |

### DoD 反模式自查

- **e2e 数量**：仅 D4 一条；其余为 integration（9 条）、unit（2 条）、static（2 条），不依赖 GUI 自动化完成全部验证。
- **优先级分布**：P0 6 条（D1–D6），P1 7 条（D7–D13），P2 1 条（D14）；不是“全 P0”。
- **独立完成**：每条只验证一个功能点；配置校验拆成 D8（单元）与 D9（启动行为），Python 版本校验独立为 D10，端口冲突独立为 D11，生命周期拆成 D12（app 启动）与 D13（外部启动）。
- **可重新制造**：全部使用临时目录、随机任务名/标记、fake 可执行文件与临时 HTTP 服务；不读取或依赖用户现有工作台数据。
- **拆分/降级建议**：
  - D4 若本机 GUI 自动化不可用，降级为“手动启动 `.app` + 截图 + 窗口标题/URL 观测”，但不得以“无法自动化”为由跳过窗口实际展示的验证。
  - D5 若无法从窗口取文本，可降级为“停止旧控制台 + 更新源码 + 重启 app + HTTP 页面抓取 + app 二进制哈希”的集成验证，并在测试报告中明确窗口展示仍由 D4 覆盖。
  - 若实现后发现 D2 的子进程命令行与“窗口 URL”必须分开取证，可将 D2 拆为 D2a（拉起命令）与 D2b（窗口 URL/就绪），但不得合并 D2 与 D3。
