# 决策定级契约

这次选择有没有改变已经确认的决定，以及这个改变要不要人负责。主体会话先核实事实，再定一个等级。

harness 把同文规则注入主体会话。`goal.md`、`spec.md`、`plan.md`、`decisions.md` 的具体路径由当次初始化填入：未绑定迭代时在 `docs/` 下，绑定迭代后在 `iterations/<名字>/` 下。本文件不写死某一次的路径。

已确认的决定写在这四份文件里。同一件事沾到多条时取最高等级。核实后仍不能证明「不改变已确认的决定」，就按 L1 提交，不能当成 L2 继续做。

## 1. 等级

### L0

增加或推翻已确认的决定。必须写入决策记录，必须人工确认。包括：

- 对外契约：接口、字段、错误语义、事件、权限，以及给其他系统的承诺。
- 持久化形态：表、字段、类型、约束、迁移是否可逆、存量数据怎么处理。
- 复用还是新建。
- 兼容策略：旧调用方、旧数据、旧接口是否继续可用。
- 改写 `goal.md`、`spec.md`、`plan.md` 或已有决策记录里已经确认的决定。

### L1

目标仍然能达到，但做法偏离已确认决定，成本或风险有明显缺口。必须写入决策记录，必须人工确认。包括：

- 同步还是异步。
- 实效性：结果要多快被看到，允许的延迟上限。
- 一致性级别：强一致、最终一致，还是读己之写。
- 失败时用户能看到的行为、可靠性或运维负担，和已确认做法相比有明显缺口。

### L2

已确认的目标、对外契约、数据形态、兼容策略、同步方式、实效性和一致性都不变。节点内自己决定，不提交定级，不写入决策记录。函数拆分、命名、目录、等价重构属于 L2。

环境问题和依赖问题先自己处理（例如 mock 掉缺的依赖）。只有缺权限、缺资料，或必须由人做外部动作时，才一次说明：失败点、已经试过什么、排除了什么、推荐路径、最少需要什么帮助。环境缺口不能记成通过。

## 2. 提交

方案开工前先扫描。只要出现 L0 或 L1，先提交定级并停下来，等人确认之前不要把决定写进决策记录，也不要在当前节点把修订做完。

判定为 L0 或 L1 时，在回复最末一行单独写出，其后不要再写别的内容。L2 不输出这一行。

| 字段 | 含义 |
|---|---|
| `level` | `L0` 或 `L1` |
| `clause` | 对照的条款 |
| `fact` | 核实到的事实 |
| `basis` | 已确认文档里的原决定 |

行的形状是 `GDD-GRADE:` 后接一行 JSON。harness 取最后一条合法行。JSON 无法解析，或 `level` 不是 `L0`、`L1`、`L2` 之一，该行作废。说明文字里的示例必须写成下面这样，`level` 用「L0 或 L1」，避免被当成一次真实定级：

```text
GDD-GRADE: {"level":"L0 或 L1","clause":"对照的条款","fact":"核实到的事实","basis":"已确认文档里的原决定"}
```

## 3. 人工确认

L0 或 L1 提交后，流水线暂停。确认键是 `等级|条款|事实`。

- 批准：从需求澄清起做增量修订，修订时把这条决定追加进决策记录。同一次修订里，同一确认键不再暂停。
- 驳回：不开始修订。同一确认键不再作为 L0 或 L1 提起，当前节点按 L2 做完。
- 修订已经在进行时，新的确认键仍要暂停。批准后留在当前节点继续，不另开一轮重跑。

## 4. 决策记录

正式文件含标题 `## 决策记录`。只追加 L0 或 L1 被确认后的条目。

每条记录是该标题下的一个小节。小节标题在文件内唯一，供以后的条目指向。正文按下面的字段各写一行：

- 等级
- 事实
- 对照的条款
- 备选
- 选定
- 原因

推翻旧决定时另起一条，增加一行 `指向：<旧小节标题>`。旧条目的文字保持原样。

未绑定迭代时，正式文件是 `docs/decisions.md`。绑定迭代后是 `iterations/<名字>/decisions.md`。增量重跑把修订稿写到 `.gdd/revision-stage/` 加上该相对路径，例如 `.gdd/revision-stage/docs/decisions.md`。重跑期间不改正式文件。

追加成立的条件：新文本以旧文本的字节为前缀。旧文本不以换行结束时，追加部分先换行，不能接在旧的最后一行后面。没有旧记录，或重跑时还没有修订稿，则不拦。

改了已有条目时，harness 退回并要求重写。同一次里再次改旧条目，按当前节点打回。正式文件相对基线副本改了旧内容时，先退回基线副本。
